# Frontend (502-frontend)

Loaded when working under `502-frontend/`; the root `CLAUDE.md` has the product, roles, resource rules and environment. Paths below (`app/`, `components/`, `hooks/`, `lib/`) are relative to `502-frontend/src/`.

## Commands

There are no frontend tests. If `node_modules` lacks packages listed in `package.json` (TypeScript cannot find `radix-ui`, `sonner`, `xlsx`), run `npm ci`. If `npm run dev` serves nothing and logs `Can't resolve 'tailwindcss' in '<repo root>'`, the Turbopack dev cache in `.next/dev` is stale (seen after the machine crashed: Turbopack then feeds `globals.css` to Tailwind without a file path, so Tailwind resolves from the parent directory): stop the server and `rm -rf .next`. The Node version is not the cause (it fails the same on Node 22 and 26).

## Architecture

- Routes are `/[branch]/sales/...`, `/[branch]/inventory/...`, `/[branch]/funds`, `/[branch]/reports/...`, `/[branch]/admin/{users,branches}`; the branch comes from the first path segment (`lib/branch.ts` `useBranchCode()`) and is sent as `?branch=` on requests. `/` is the login page (`app/(auth)/page.tsx`); after login the app goes to `/<own branch>/sales/rooms`.
- `components/auth-provider.tsx` bootstraps the session (`GET /auth/me` + `GET /branches`), redirects a non-chain-manager whose URL names another branch, signs out when the 24-hour session ends (timer on `sessionExpiresAt`) or a refresh fails (`onSessionExpired`), and auto-logs-out after 15 hours of inactivity.
- **Shell** (`app/[branch]/layout.tsx` → `components/layout/app-shell.tsx`, shadcn dashboard-01/sidebar-07 pattern): `AppSidebar` (inset, collapsible to icons, a sheet on phones; open state in the `sidebar_state` cookie) with `BranchSwitcher` and `NavUser`, `SiteHeader` (breadcrumb, business day, theme toggle), then the page inside a `@container/main` wrapper keyed by pathname, which fades/slides each page in. A room page (`/[branch]/sales/rooms/<id>`, `FULL_SCREEN` in `app-shell.tsx`) is full screen: no sidebar and no `SiteHeader`, and it splits Thực đơn & PR/KTV | Hóa đơn half and half from a `@2xl/main` width (stacked below, bill first); the menu is a vertical list (one row per product: name, stock, ×in bill, price); side by side both cards are as tall as the menu card showing 10 dishes, capped at the screen height (`PANEL_HEIGHT`), and the menu, the PR tiles and the bill scroll inside them, so Thanh toán stays in view. `lib/navigation.ts` is the single nav config: sidebar groups, breadcrumb and titles. Pages start with `PageHeader` (title, description, actions); a page can set the breadcrumb/tab title with `usePageTitle` (`components/layout/page-title.tsx`). Tab titles come from a `layout.tsx` with `metadata` per route (template `%s · Karaoke 502` in `app/layout.tsx`).
- `lib/permissions.ts` is the UI copy of the permission matrix (`can(user, perm)`, `canVisit(user, path)`; `pr`/`pr.view` are also granted by `user.managesPr`); `components/route-guard.tsx` shows `Forbidden` for pages the role can't use, and the sidebar only lists the pages the role may use. This only hides UI; the backend enforces access.
- `lib/api.ts` is the single axios instance: access token and session end kept **in memory** (`setSession`, `onSessionChange`), `withCredentials` for the refresh cookie, and a 401 interceptor that calls `/auth/refresh` once and retries (so a page load logs one expected 401 on `/auth/me`); it skips `/auth/login|refresh|logout`. A failed refresh fires `onSessionExpired` and marks the error (`isSessionEnded`) so `useNotify` does not toast it. `next.config.ts` sends the security headers (CSP in production builds only; the dev server needs eval) — a new external script, font or API origin must be added to its CSP. `apiErrorMessage(error, fallback)` extracts the server's Vietnamese message.
- All pages are client components calling the API directly. Shared pieces: `hooks/use-api-data.ts` (GET + reload), `hooks/use-notify.ts` (sonner toasts for success / API errors), `hooks/use-now.ts` (ticking clock for live timers and totals), `hooks/use-polling.ts` (periodic refresh that pauses while the tab is hidden and runs once when it comes back; the room map refreshes rooms every 30 s and the floor staff every 5 min, the room page its order every 15 s; the cashier and manager screens slow the room map, the room page and the badge to 60 s while the live socket is up, see Live events), `lib/types.ts` (API shapes), `lib/labels.ts` (Vietnamese labels of enums), `lib/format.ts` (money/date; `toDateInput` gives local YYYY-MM-DD — don't use `toISOString()` for dates; `businessDate()` is today's business day), `components/data-states.tsx` (`EmptyState`, `TableEmpty`, `TableSkeleton`, `ListLimitNotice` — "only the newest N of M" above a capped list, with the total from `totalCountOf(res)` in `lib/api.ts`), `confirm-dialog.tsx` / `reason-dialog.tsx` (AlertDialog confirm; cancel with a required reason), `date-range-picker.tsx` (`DateRangePicker`: presets + Vietnamese calendar; `DatePicker`: the same box for one business day, with `max` — use these, never `<input type="date">`), `line-items-table.tsx`, `components/catalog/*` (room/category/product managers used by both Bán hàng and Kho settings), `components/sales/*` (checkout dialog, open-room dialog, bill sheet, `BillSummary`), `components/inventory/stock-document-form.tsx`.
- **Live events**: `components/live-events-provider.tsx` (mounted in `AppShell`, sales roles only — permission `live`) holds the one WebSocket (`lib/live-events.ts` `liveUrl()`: `/api/ws` next to `NEXT_PUBLIC_API_URL`, `wss:` on https), sends `auth` on open and on every `onSessionChange`, reconnects with 1, 2, 4… ≤ 30 s + jitter (30 s flat after 1013), keeps the socket while the tab is hidden and closes it on logout. A close 4001/4002 while a token is held (the token ran out in a hidden tab) makes it call `refreshSession()` (`lib/api.ts`, shares the sign-out path with the 401 interceptor) and reconnect at once, or, if that reconnect is refused again before `ready`, back off normally; a new token while no socket is open also reconnects at once. `hooks/use-live-events.ts`: `useLiveEvent(handler)`, `useLiveConnected()` (true from `ready` until 30 s after a drop), `useLiveInterval(connectedMs, disconnectedMs)`; `hooks/use-coalesced.ts` merges a burst of signals into one reload. Consumers: the room map (`room.changed` of the URL's branch → `/rooms`, 60 s / 30 s), the room page (`order.changed`/`discount.decided` of its order → `/orders/:id`, 60 s / 15 s), the badge and the queue (`discount.requested`/`discount.decided`, 60 s / 15 s); the provider's local `reconnected` event makes each reload once after a gap. The socket only signals: every screen still works on polling alone.
- **Excel import** (`/[branch]/imports?type=…`, `components/excel-import/*`, `lib/excel-import/*`): a 4-step wizard (file → column mapping → dry-run preview → done). `workbook.ts` reads xlsx/xls/csv with SheetJS (`xlsx`, installed from the official `cdn.sheetjs.com` tarball because the npm release is outdated; always `await import("xlsx")` so it stays out of the main bundle; CSV is read as text for UTF-8). `definitions.ts` declares, per import type, the fields (label, kind, required, header aliases, template example) — add a field there and in the backend DTO together. `mapping.ts` guesses the mapping (remembered headers in `localStorage` `excel-import:<type>`, then aliases, compared without diacritics); `parse.ts` reads cells (Vietnamese number formats, Có/Không, enum labels) and reports unreadable cells before anything is sent. List pages link to it with `ExcelImportButton`.
- **Phone layouts**: pages are laid out with container queries on `@container/main` (not viewport breakpoints), since the sidebar takes part of the width. Wide tables hide secondary columns with `SHOW_FROM.{xs,sm,md,lg}` from `lib/responsive.ts` (and show a short stand-in under the first column with `ONLY_NARROW`); `TableSkeleton` takes the same per-column classes. Tables inside sheets/dialogs are portaled outside `@container/main`, so they use viewport breakpoints (`sm:`). Check new screens at 360–390px wide: no page may scroll sideways.
- UI primitives live in `components/ui`: shadcn new-york (v4 registry) components on the `radix-ui` package, with sr-only texts translated to Vietnamese and `success`/`warning` Badge variants. Theme tokens (slate base plus `--success`/`--warning`, chart colors) are in `app/globals.css`; dark mode via `next-themes` (`components/theme-provider.tsx`, `theme-toggle.tsx`). Font: Inter, bundled with the app (`@fontsource-variable/inter` imported in `app/layout.tsx`; variable weights, Vietnamese subset), so nothing is fetched from Google Fonts at build or run time — don't reintroduce `next/font/google`. `--font-sans` in `globals.css` ends with the system sans-serif fonts so a failed font load never shows a serif font; `font-mono` is Tailwind's system monospace stack. Add new primitives with the shadcn CLI (`npx shadcn@latest add <name>`) to stay consistent with `components.json`, and check that it did not add stray packages.
- **Reports** pages (`app/[branch]/reports/*`) keep their filters in the URL (`hooks/use-report-filters.ts`: `from`, `to`, `groupBy`, `compare=1`, `scope=chain` for the chain manager) and share `components/reports/report-toolbar.tsx`, `components/stat-tile.tsx` (with the Δ% badge) and `lib/excel-export.ts` (`toSheet` + `exportWorkbook`, SheetJS loaded on demand). Permissions `reports` (managers), `reports.revenue` (the Doanh thu page: managers and the cashier; `sales.reports`, the Hóa đơn page, has the same roles) and `reports.chain` (chain manager). An option of a page (Theo phòng | Theo loại phòng, the sort of Thống kê PR) is a `Tabs`/`TabsList`, not an outline `ToggleGroup`. `/sales/statistics`, `/sales/statistics/{cskh,revenue}` and `/sales/overview` redirect to `/reports/revenue`; Hóa đơn stays at `/sales/statistics/bills` (named "Quản lý bán hàng" in the sidebar only: `NavItem.sidebarTitle`). Each report's Excel sheet is built by `lib/report-sheets.ts` (one builder per sheet, from the API response), used both by the report pages' own export and by **Tải báo cáo** (`/[branch]/admin/reports`, sidebar group Quản trị, permission `reports`): pick reports (`lib/report-downloads.ts`, one sheet per choice), a date range, the period grouping and the scope, then one workbook with one sheet per report (built two reports at a time, `mapWithLimit`, so the download does not hold every database connection); Sổ quỹ and Hóa đơn are branch-only and ≤ 366 days there (Hóa đơn warns when the 1000-bill cap of `GET /orders` cut the sheet). Add a new report's columns to `report-sheets.ts`, not to its page. List pages export with `components/export-excel-button.tsx` + `lib/excel-export.ts`: Sổ quỹ (summary with a column per method, entries as filtered), Hóa đơn (the bills as filtered, `billsSheet` in `report-sheets.ts`: every column incl. CSKH, phục vụ, thu ngân, tiền giờ/hàng and their discounts, VAT, the items; amounts only on paid bills, a last row summing them), Danh mục hàng (products and categories, headers matching the import template). `SiteHeader` is sticky. The breakdown pages keep their own option in the URL with `useReportOption` (`?role`, `?by`, `?metric`; `setFilters` keeps them), query with `rangeParams` (no periods), hide the period controls with `<ReportToolbar periods={false}>`, and read their scope from the response with `useReportScope`. Shared pieces: `components/reports/{ranking-chart,heatmap}.tsx`, `lib/report-columns.ts` (`METRIC_COLUMNS`). `/reports/branches` is chain-manager only (`reports.chain`). `/reports/profit` (Lãi lỗ: periods as columns, by month by default via `useReportFilters({ groupBy: "month" })`, `ReportToolbar compare={false}`, lines from `lib/profit.ts`) `/reports/inventory` (Nhập – xuất – tồn, category filter in the page) and `/reports/stock` (**Tồn kho** by quantity: the same `GET /reports/inventory`, quantities only — tồn đầu, nhập, xuất, tồn cuối — with search, category and Hết hàng filters, a row opens the product's Sổ kho, `components/inventory/product-ledger-sheet.tsx`; its Excel sheet `stockQuantitySheet` lists every product whatever the filters, plus the detail nhập theo phiếu / bán / phiếu xuất / hoàn – điều chỉnh) complete the Báo cáo group. Tồn kho replaced the Kho › Tồn kho page: `/inventory/stock` redirects to `/reports/stock` and `/inventory` to `/inventory/documents`; amounts that carry cents (costs) are shown with `formatAmount`.
- **PR/KTV** pages (sidebar group after Bán hàng): `/[branch]/pr/attendance` (Điểm danh: the standard `DatePicker` defaulting to the business day, no future day, one row per active PR/KTV plus anyone called that day who has since left; Vào/Ra buttons for today, a time dialog for past days, edit/undo per entry) and `/[branch]/pr/staff` (**Thống kê PR**: a date range, hours in rooms / visits / rooms per PR, sorted with the Theo tên | Theo số giờ tabs, a total row from the API's `totals`; the page also keeps adding/editing/leaving/removing PR/KTV). In the room page the left card is "Thực đơn & PR/KTV" with the **Thực đơn | PR/KTV** tabs for whoever can sell, and only "PR/KTV" for a PR manager who cannot sell; the **PR/KTV** tab (`components/sales/{pr-picker,room-pr-list}.tsx`, permission `pr.assign` — `can()` ignores `managesPr` for BOARD) picks a PR to give the time in, **Ra** ends it, **Sửa giờ**/**Xóa** fix a mistaken entry (only while the room is open; the edit dialog sends only changed fields); every write goes through the room page's `enqueue`/`saveOrder`/`runOrderAction` queue, and the visits arrive with the order's 15 s polling (the picker list is loaded when the tab opens and when the room's visits change, no polling of its own). `useApiData` also returns `total` (the `X-Total-Count` header).
- The room map shows a session's time as `N phút` up to 60 minutes, then `XhYYp` (`formatElapsed` in `lib/format.ts`); the Hóa đơn list shows the duration as HH:mm (`formatClock`) and CSKH and Phục vụ in two columns. The stock ledger names the bill of a sale by its number (`billLabel`), and the staff report's Excel sheet adds "Tổng doanh thu trước giảm giá" (tiền giờ + tiền hàng before discounts, before VAT).
- **Room page by role, time lock, discounts** (`app/[branch]/sales/rooms/[id]`): what a screen shows follows `can()` and `isServerOf(user, order)` in `lib/permissions.ts` (`STAFF` whose id is the order's `serverId`). The room's phục vụ gets the Thực đơn and PR/KTV tabs, edits items and can **Chốt giờ**; the CSKH sees the room read only; **Mở khóa giờ** is for the sales roles (`canOperate`). Once `timeLockedAt` is set the room fee stops there (the page's live bill uses it as `endTime`, a "Đã chốt" badge shows) and the room map (`sales/rooms`) shows **Chờ TT** with the time up to the lock instead of the running clock. `sales.editPaid` and `sales.void` (correcting or voiding a paid bill) are chain manager only; `discounts.approve` is the managers, `discounts.view` adds BOARD.
- **Discounts with approval**: `components/sales/bill-adjustments.tsx` (the Giảm giá & thuế card of the room page) keeps a **local draft** of the five adjustments (`Adjustments`; `lib/discount-rules.ts` mirrors the backend rules: `needsApproval` = any discount up, a percent dropped over an amount, or VAT down, `changedKeys`, `adjustmentsOf`, `ADJUSTMENT_LABELS`). **Each row** (Giảm giá món, Giảm giá giờ, Thuế VAT) has its own small button after the two inputs, and each row is sent on its own (`POST /orders/:id/adjustments` with that row's values over the saved ones): a **send** icon while the row differs from what is saved — it applies at once for a manager (`discounts.approve`) or a change that makes nothing cheaper, and otherwise opens the `ReasonDialog` (required note) and creates a `DiscountRequest`; a **green check** when the row equals the saved values and carries one (typing a value back to the saved one returns to the check); nothing for an untouched empty row. The pending row shows the sent values read only with a "Chờ duyệt" badge and an **✕** that cancels the request; the other rows stay editable but cannot be sent until it is decided (one pending request per order). The bill, Tạm tính and the Thanh toán amount keep the saved values until approval. **Thanh toán stays enabled**: with a request pending it opens a warning (`ConfirmDialog`, `cancelLabel` "Chờ duyệt") whose confirm cancels the request and then opens the checkout at the undiscounted price (the server refuses a checkout while a request is pending). The page remounts the card with a `key` of the saved values plus the pending request id, so a poll or a decision resets the draft without an effect. When the pending request leaves the order (seen by the 15 s polling), the page fetches `GET /discount-requests/:id` once and toasts the outcome (đã duyệt by whom / từ chối with the note / hết hạn).
- **Duyệt giảm giá** (`/[branch]/sales/discounts`, `components/discounts/*`, sidebar item under Bán hàng, permission `discounts.view`): tabs **Chờ duyệt** (managers only: cards from `GET /discount-requests/pending`, capped at 200 with `ListLimitNotice`, polled every 15 s, or 60 s while the live socket is up; **Duyệt** / **Từ chối** — the reject dialog is `ReasonDialog` with a required note; the chain manager sees every branch's requests, a 409 toast names whoever decided first) and **Nhật ký** (everyone who can view: `GET /discount-requests` of the current branch and a business-day range, capped at 500, a status badge and the `AdjustmentDiff` of each change, requests, direct applications and paid-bill edits). `hooks/use-pending-discounts.ts` (called by `AppSidebar`, managers only, 15 s through `usePolling`, 60 s while the live socket is up) polls `GET /discount-requests/pending-count` for the sidebar badge and toasts "Có yêu cầu giảm giá mới" when the count grows (never on first load); the page fires the `DISCOUNTS_CHANGED` window event after a decision so the badge reloads at once.
- **Hóa đơn điện tử** (`/[branch]/sales/einvoices`, `components/einvoices/*`): see `src/components/einvoices/CLAUDE.md`.
- **Accounts page**: the account form warns (in `text-warning`) when the position is Phục vụ and the account has no password (a new account with the password left empty, or an existing one with `hasPassword` false), since a phục vụ needs to log in to serve a room.
- Old addresses redirect: `sales/catalog/*` to `sales/settings`, `sales/room-management` to `sales/rooms`, and `sales/overview`, `sales/statistics` and `sales/statistics/{cskh,revenue}` to `/reports/revenue`.
